# 图 2 的物理来源与复绘

图 2 采用 [SKY130HD AES 几何邻网与在线诊断对照](../../../../project_docs/evidence/tcad_geo_neighbor_20261125/REPORT.md) 中正序在线诊断臂的第 3 次请求。该三门提议包含 `_12777_`、`_20883_` 和 `_21033_`。四个面板以 `_21033_` 的左下角为原点，从该处裁取同一范围。数据文件保存原点、双端点的所绘线网 DEF 记录、目标单元 met1 矩形、DRC 标记及各来源的 SHA-256。

| 面板 | 来源与绘制范围 |
| --- | --- |
| (a) | 冻结合法参考 `6_final.def` 中的实例坐标和五条所选线网。实线表示 met1 中心线，虚线表示其他层中心线，小圆表示低层过孔位置。LEF 提供目标单元轮廓、met1 引脚、障碍和电源轨。 |
| (b) | 根据归档 `preview.tcl` 重建现场预览。在原坐标换成 `xor2_2`，清除直连网旧布线并保留其余导线。历史报告记录五个标记，图中按原坐标绘制此局部的三个 `_21033_` 与 `net8148` 的 met1 短路标记。三个标记框有重叠。 |
| (c) | 按正文窗口定义从替换后 BBox 各向外扩一行高（2.72 µm）。该图层是对真实几何的窗口标注，历史现场标记来自全块预检。标记报告将此处冲突归因到 `net8148`，另两个邻网位于本裁图之外。 |
| (d) | 通过原验收的 `routed.def`。`net8148` 释放后几何变化，`_08943_` 被在线臂固定且整个 DEF 布线记录的各路径（含过孔及 `RECT`）与冻结参考一致。该保护网被几何接触臂额外放行。两份干净物理端点均有空的全块 DRC 报告。 |

归档读回每次先解析目标和相邻实例位置、标记、放行集合及保护名单，再比对所绘保护网的全路径记录。历史 `routing_audit.json` 同样记录保护网几何变化数为零。图内彩色线宽用于辨认类别，线网位置采用 DEF 中心线，目标单元和 DRC 的矩形按物理坐标绘制。

```bash
python extract_fig2_aes_geometry_r6.py \
  --archive-root <SKY130HD-holdout-archive> \
  --cell-lef <sky130_fd_sc_hd_merged.lef> \
  --output fig2_aes_geometry_r6.json
python plot_fig2_aes_geometry_r6.py
```

第二步可直接使用随稿 JSON，通过 Matplotlib 复绘 PDF，无需 OpenROAD。`--previews` 同时导出 SVG 和 600 dpi PNG。`--with-alignment` 使用已安装的 `audit_panel_alignment` 写出布局检查收据。

交叉验证涵盖目标同址换门、来源提议一致性、端点有效及 SEC、三处实际短路标记位于窗口、归因集合一致、完整保护网路径不变。图幅轴区对齐通过，最小字形为数学下标 5.95 pt，普通标注至少 8.05 pt。渲染审计 0 个失败，8 个提示均为文本背景与浅灰的实际邻居单元框有边缘交叠，已逐面板核读文字和引导线。
