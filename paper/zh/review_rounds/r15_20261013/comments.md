# r15 —— 用户"正式期刊审稿人视角"通读意见（第二轮去防御化）

> 用户原文（2026-10-13），逐字保留。

我重新按**正式期刊审稿人（Integration / TODAES / TVLSI 方向）视角**通读了这一版全文。重点不是找错别字，而是检查：

1. 论文叙事逻辑是否自然
2. 贡献是否被正确表达
3. 是否存在过度防御、过度声明
4. 方法—实验—结论是否闭环
5. 哪些地方应该"少解释，多陈述"

先给总体判断：

> 这一版技术内容已经比较成熟，但文字风格仍有明显"答辩稿/项目报告"痕迹。最大的问题不是 claim 过强，而是作者过于主动解释审稿人可能的问题，导致主线贡献被稀释。

论文现在应该从"证明我没有问题"转向"清楚告诉读者我做了什么、发现什么"。

---

## 一、摘要审查

当前摘要比之前好很多。开头「随着集成电路规模与设计复杂度持续提升，时序收敛已成为数字芯片设计流程中的关键挑战。」是正确的，解决了之前"小众入口"的问题。阅读路径 大背景 → ECO → pre-placement ECO → FAECO 合理。

**问题 1：摘要后半部分仍偏"实验报告"。** 当前「消融实验显示，指数滑动平均失效反馈未带来额外收益，结构重综合候选也未带来额外 WNS 改善；逻辑深度降低不等于 WNS 改善……」不是错误，但摘要空间有限，现在花了很多字解释"哪些东西没有提升"，会降低第一印象。

建议：保留一个负结果即可。例如改为「消融实验进一步揭示候选反馈机制和结构重综合候选的性能边界。」——比"EMA 没有收益 + S 没有收益 + 深度不等于 WNS"更像期刊摘要。原因：摘要应该突出**发现**，而不是**失败列表**。

## 二、引言审查

### 1.1 背景
整体很好。但「上述方法留下三个需要在公开工具链上量化的问题……」是典型的防御式写法（作者在解释"为什么我要做实验"，而论文不需要）。建议改成主动陈述：「因此，预布局门级 ECO 仍需要解决三个问题：」然后列 1. 候选空间扩展；2. 验证成本控制；3. 失效分析。区别：前者像回应审稿人，后者像提出研究问题。

## 三、贡献部分审查

**Contribution 1**：「通过多类型局部修改候选生成与候选排序扩展搜索空间，并降低候选验证开销。」很好。但后面「在固定权重、20 轮迭代配置下……」建议移走——贡献不是实验结果。推荐：贡献写到"提出候选探索框架……"结束，实验数字放摘要和实验章节。

**Contribution 2**：「并利用失效信息分析候选搜索瓶颈、调整后续候选生成策略。」比之前好，但"调整后续候选生成策略"稍强（因为实验显示 EMA 没有性能收益）。建议改为"辅助分析候选搜索瓶颈和候选生成策略调整。"增加"辅助"。

## 四、相关工作审查

最大的问题：**过度解释为什么不能比较**。当前「上述方法依赖不同的输入与基础设施，其与直接定量比较之间的主要障碍汇总于表 2。本文因此基于公开工具链建立统一实验环境……」逻辑没问题，但语气像提前辩护。建议压缩为一句：「由于不同方法依赖不同输入阶段和评价目标，本文基于公开工具链建立统一实验环境，重点比较候选空间扩展、候选排序和验证开销。」表 2 已经承担解释作用，正文不要重复。

## 五、方法章节审查

**3.3 加权割**：这一段「对于缺少 R 等价候选的节点，继续施加深度折扣可能使搜索偏向无法实例化为 R 候选的边界……」太像代码注释，不像论文。建议删除，或压缩成一句：「R 相关折扣仅作用于具备 R 候选的节点。」论文不需要解释所有实现异常路径。

**3.4 Feature motivation**：当前「降低引入电气与负载风险的可能」稍微像理论保证。建议改「降低高负载节点被优先选择的概率。」统一：所有 feature 描述使用 倾向/偏好/抑制，不要 避免/保证/降低风险。

## 六、实验章节审查

**4.1 实验设置**：「本文将 WNS 改善作为评价指标，不讨论完整时序收敛」是典型防御。建议改「本文采用 WNS 改善作为主要评价指标。」即可。因为"不讨论"听起来像"这个我没有做到"，而实际上实验目标本来就是 WNS 改善。

## 七、4.4 消融实验

现在已经改得很好。尤其「第一组在 20 轮迭代预算下评估候选空间扩展与候选评估顺序……」是正确的。「不单独隔离式 (2) 中各特征项贡献」已经删掉，很好，现在不要再补。

## 八、物理验证章节

当前「用于观察接受候选在物理估计下的时序表现。」很好。但结尾「不等同于物理实现有效性的验证」仍有防御味。建议改「用于分析预布局筛选结果在寄生估计条件下的稳定性。」更积极。

## 九、结论审查

当前结论整体不错。但最后「为后续预布局 ECO 搜索策略设计提供依据。」略弱（论文不是综述）。建议改「为预布局 ECO 候选探索策略设计提供参考。」更直接。

## 十、全文防御性语言统计（人工审查）

需要重点清理：
1. 「不讨论」（不讨论完整时序收敛）→ 替换为「采用 XXX 作为指标」。
2. 「不等同于」（不等同于时序收敛 / 不等同于物理实现有效性）→ 保留一次即可。
3. 「不主张」（不主张权重理论最优性）→ 建议删除，改「表 4 总结各特征在候选排序中的作用。」已经够。
4. 「未带来额外收益」→ 实验结论可以保留，但不要大量出现。

## 十一、最需要改的 10 句话

| 位置 | 问题 | 建议 |
| - | - | - |
| 摘要 | 负结果太多 | 压缩 |
| 引言问题定义 | "留下三个问题" | 改研究问题 |
| 贡献 1 | 带实验数字 | 移实验 |
| 贡献 2 | 调整策略过强 | 弱化 |
| Related Work | 解释不能比较太长 | 压缩 |
| 方法 | 代码级异常解释 | 删除 |
| Feature | 风险语言过强 | 改倾向 |
| 实验设置 | 不讨论收敛 | 改评价指标 |
| 物理验证 | 防御说明 | 改稳定性分析 |
| 结论 | 参考依据 | 改总结发现 |

## 最终审稿结论

技术部分 ✅ 足够；实验部分 ✅ 足够。剩余工作**不是增加内容，而是减少解释性文字，提高陈述力度**。最终目标：从"我们知道可能被质疑，所以提前解释"变成"这是方法，这是观察，这是边界"。你现在最值得做的是一次**全篇去防御化编辑**，不是技术修改。
