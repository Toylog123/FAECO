# r21：B 族主结果的 STA 计数后续核查

日期：2026-10-14。范围：只读 ITC-99 19 实例的既有 JSON；b17 使用主结果指定的 180 s 重跑，不使用默认 60 s 的大台账。未运行 EDA，未改论文或共享记录。

**结论：正文 3363、b06 的 664、b17 的 104 均确认为候选评估记录数，应避免称为真实新增 STA 测量次数。可以保留原数字并修正指标名。** 18 个实例可以从 provenance 与缓存标记确认 2890 条新 STA 结果；b17 的旧 schema 不提供这类标记，19 实例的新 STA 总数不能仅据现有 JSON 唯一确定。

## 源与读取规则

- 主结果列表：`experiments/20260826_aggregation/summary.json → itc99[]`。
- b01--b15、b20--b22：`experiments/20260826_itc99_main/<c>/<c>/eval_trials.json → trials`。
- b17：`experiments/20260908_phase2_b17_resume/b17/eval_trials.json → trials`；对应 `outerloop_result.json`。
- 全部评估记录 = `len(trials)`。
- 带 STA 来源的有效结果 = `sta_provenance` 为字典且 `wns` 为有限数值。
- 可确认新 STA 结果 = 上述结果中 `skipped_duplicate` 非 true；报告路径去重作为交叉检查。
- 18 个新 schema 的缓存记录还用 cache_key、wns 与 report_path 核查：59 条带 provenance 的缓存复用均对应本运行中更早的原始测量，无缺失 report_path 或未匹配缓存。

这 18 实例的全部 trials 中还有合计 228 条 `skipped_duplicate=true`；其中只有 59 条带 STA provenance，其余 169 条为没有新 STA 来源的重复/跳过记录。不能把“全部缓存/重复标记数 228”直接从 provenance 分母 2949 中扣除。

## 关键三项建议

1. **3363：** 改称“19 电路共进行 3363 次候选评估/产生 3363 条候选评估记录”。该数字不应作为真实 OpenSTA 调用总数。若要额外报告真实 STA，必须另列“18 个有来源实例可确认 2890 次，b17 旧台账未保存计数来源”。不建议在正文硬拼一个 19 实例的精确新 STA 数。
2. **b06 的 664：** 改称“664 条候选评估记录中未观察到严格 WNS 改善”。现有可确认新 STA 是 597，provenance 结果共 602（含 5 缓存），而全部记录为 664。只需纠正单位，原来“无严格改善”的观察不因此失效。
3. **b17 的 104：** 改称“104 条候选评估记录内取得 +0.38 ns 改善”。该旧台账全部 104 条均没有 `sta_provenance`、`cache_key`、`skipped_duplicate` 与运行耗时字段，`outerloop_result.json` 也没有预算 used 或 B(k) 字段。不能应用 D 的筛选规则把它误判为“0 次测量”，也不能反向假定 104 条都是新测量。缺失来源属于 schema 差异，保留为未识别。

默认批次的 4044 与 F1--F6 表已经称为候选评估分母，本次没有重新解析约 1.49 GB 的默认 b17 台账；也没有将默认 60 s 的 785 条混入当前主结果的 104 条。因此本核查不改变 F1--F6 失效分布数字。

## 复核边界

上述“新 STA 结果”是按 JSON 的来源与缓存标记识别的候选级结果，排除了可识别的缓存重放，并得到唯一报告路径印证；不包括初始基线 STA、当前网表刷新、最终物理评估与 SEC。B 历史族 revision 未完整绑定的限制继续存在。此报告证明计数单位，不提供新 EDA 实验或新的性能结论。
