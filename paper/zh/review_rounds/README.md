# 审稿轮次归档

## 机制说明（为什么这样设计）

论文修改会经历多轮审稿。若把各轮意见、回复、旧版本散落在 `manuscript/`、`responses/`、临时文件夹中，会出现：

- **新旧版本混淆**：不知道哪版对应哪轮意见；
- **文件糅杂**：意见、回复、草稿堆在一起，难以回溯"这轮改了什么"。

因此采用**每轮一个独立文件夹、自包含归档**：`r<N>_<日期>/` 内固定放三件（意见 / 回复 / 修改前论文），结构统一、命名规范，任何时间都能完整重现某一轮审稿前后的状态。

## 目录卫生（保证不糅杂）

1. **每轮一个文件夹**，命名 `r<N>_<YYYYMMDD>`（如 `r1_20260811`）。
2. **文件夹内固定 4 个文件**：`README.md` / `comments.md` / `response.md` / `manuscript_before.tex`，不额外堆放。
3. **归档只读**：归档后不修改；补充说明写轮次 `README.md`。
4. **活动文件不散落**：审稿意见 / 回复只在轮次文件夹内；`manuscript/` 只放当前最新稿；`responses/` 只放当前轮回复。
5. **不建临时文件夹**：不要用 `tmp/`、`review_tmp/` 等堆放审稿文件。
6. 每轮结束后，清理轮次文件夹外的临时笔记。

## 结构

```text
paper/zh/review_rounds/
|- r1_YYYYMMDD/                  # 第 1 轮（日期）
|  |- README.md                  # 轮次说明（轮次、日期、审稿范围、改动摘要）
|  |- comments.md                # 该轮审稿意见（原文）
|  |- response.md                # 该轮审稿回复
|  `- manuscript_before.tex      # 该轮修改前的论文版本
`- r2_YYYYMMDD/ …                # 第 2 轮…
```

## 操作流程

1. 收到审稿意见 → 建 `r<N>_<YYYYMMDD>/`。
2. 归档三件：意见原文（`comments.md`）、修改前论文（把当前 `manuscript/*.tex` 复制为 `manuscript_before.tex`）、回复（`response.md`）。
3. 在 `manuscript/` 修改、`responses/` 起草回复，均按「优先补实验 / 完善设计，而非降级描述」。
4. 本轮完成后，回复定稿复制进 `r<N>/response.md`。
5. 下一轮重复（当前稿即下轮"修改前版本"）。
