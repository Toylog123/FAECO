稿件的**记账纪律与负结果诚实度明显高于同类中文稿件**，但作为一篇"时序 ECO 方法"论文，它同时存在**问题定义与工业 ECO 语义错位、无任何外部基线、以及核心前提（有限 STA 预算）在自身数据中从未被触发**三处硬伤；此外全部结论建立在 11–228 单元、单角 TT、仅 WNS 的设定上，尚不足以支撑面向签核的主张。

**A3. 功能论证的模型边界说得比多数 ECO 论文清楚。**（行 246–248、补充材料 S1）
R/G/B/JOINT 不改写触发器/时钟/复位；SEC 采用"对应寄存器初态相等、允许共同初值任意"的二态模型，明确不假设两侧独立任意初态自行同步；并明确真实三态、显式 Z 不在支持域，b09/b20/b21 只保留时序观察不计入功能通过（行 331）。这个分层是正确处理。

**A4. 三类成本分开计数，且明确拒绝把它们互相替代。**（行 150、214、295）
局部检查 / 候选 STA / 最终 SEC 三者分账，缓存命中与前置拒绝不计入新 STA。这个口径在 ECO 类文献里经常被混淆。

**A5. 双侧 SPEF 后验的做法本身是正确的。**（行 433–437）
两侧各自生成寄生、同网表控制差值 0、逐次核对 8 次注释回放无未注释驱动，并主动废弃了此前"共用基线 SPEF"的失败归档（补充材料 S3）。方法学上比常见的"只跑一次 extraction"更严谨。

**C1｜"ECO"的问题定义与"预布局"的设定自相矛盾，且缺失工业上最自然的对照**

- **位置**：行 127（引言第一段的动机）、行 158（问题定义）、行 400（"受控 W1 的 8 对端点网表…标准单元数及独立缓冲单元数均不变"）、标题与行 85。
- **问题**：
  1. 行 127 用"设计后期的修改范围受到验证成本和实现扰动约束，重新综合整个设计往往难以保留已有实现"作为**采用 ECO 的动机**；但实验设定是预布局、无布局、无冻结网表、可自由改变单元尺寸与拓扑，此时"实现扰动"根本不存在——重新综合或重跑时序驱动映射是完全可行的。**动机来自后期 ECO，方法却运行在前期，两者不共享约束**。这是全文最容易被一句话打回的逻辑缺口。
  2. 真正的 ECO 语义包含 spare cell 可用性、metal-only 层限制、ECO 掩模成本、布局合法化扰动与 ECO 布线拥塞。全文（含补充材料）对此**零讨论**，连"本方法不涉及 spare cell / metal-only"这句边界声明都没有。而引用的 `ho2010eco` 恰恰是 spare cell + technology remapping 的工作（行 146、469），形成"引用后期 ECO、实现前期改动"的错配。
  3. 由于不受这些约束，本文实际做的是**离散升档 + 同功能换族**（见 M5），这在预布局等价于"时序驱动 sizing 的一阶做法"。
- **修改建议**：
  - 把"ECO"在文中**重新定义并收紧**：在行 158 前增加一段，明确本文处理的是 *pre-placement / early-stage netlist ECO*，其约束是"保留已验证的 RTL 与功能、限制改动局部性以降低后续验证成本"，而**不**受 spare cell / metal-only / 布局冻结约束；并给出与 signoff 后 ECO 的差异表（一行三列即可：改动自由度 / 是否受 spare cell 限制 / 扰动对象）。
  - 在行 127 删除或改写"实现扰动"这一动机句，改为"预布局阶段改动不引入布局扰动，但每次候选都需一次 STA，测量成本是主要瓶颈"——这样动机与方法才同源。
  - 在相关工作（行 146 后）新增一段"ECO 的流程约束"，只做**定性描述**：后期 ECO 需在 spare cell 集合内实现、常限制在金属层、需保持布局与时序模型不变；并说明本文不建模这些约束、因此结论不外推到 signoff 后修补。【不依赖新实验】
  - 补一句诚实的适用边界（可放在 5.1，行 457 附近）："若设计已进入布局后阶段，本文的候选集（换族/升档/插 buffer）不再可直接实施"。

**C4｜收益量级与违例量级严重不匹配，"修复时序违例"的主张不成立；约束设定也缺依据**

- **位置**：行 94（摘要"平均改善 0.161 ns"）、行 301、行 256（"ISCAS89 与 ITC-99 采用 0.5 ns 周期"）、补充材料表 S5（`tab:pr8`，行 538–545：基线 WNS −0.27 / −0.98 / −1.56 / −1.63 / −1.33 / −1.19 / −1.23 / −1.31 ns）、补充材料行 307（b20/b21 基线 $\le -13$ ns）、行 329（b17 从 −16.53 到 −16.15）。
- **问题**：
  1. 以补充材料表 S5 的预布局基线计，8 个电路平均违例约 **−1.19 ns**，而受控收益 0.161 ns 只覆盖约 **13.5%**，且**没有任何一个电路收敛**（最好的 s27 也停在 −0.18 ns）。单轮实验里 s420 的接受候选只带来 **+0.01 ns**（补充材料行 267 明确写了），而该电路违例 −1.55 ns——改善了违例的 0.6%。b17 用一次 G 换取 0.38 ns / 16.53 ns = 2.3%。
  2. 所有电路统一用 0.5 ns 周期，导致违例深度从 0.27 ns 到 16 ns 跨越 60 倍。当违例是时钟周期的 **26–32 倍**（b20/b21 @ 0.5 ns）时，这个网表在物理上不可能在 0.5 ns 收敛，"ΔWNS"测的是"在一个人为过度约束下能抢回多少"，不是 ECO 修复能力。真实 ECO 的违例通常在周期的 2%–10%。
  3. 因此行 94/463 的"修复时序违例"与行 127 的"以修复时序违例"属于**超出证据的表述**。
- **修改建议**：
  - 全文把"修复/repair"改为"改善/局部改善"，摘要首句与结论（行 463）必须改；在 4.1 开头（行 301 前）明确写出"本文不主张收敛，只主张在固定预算下的单调改善"。
  - 增加一列**收益占违例比例**（$\Delta$WNS / |WNS_baseline|）。这一列用现有数据即可算出，无需新实验，且能立刻让读者看到 0.6%–13% 的真实量级——诚实且有说服力。
  - 说明 0.5 ns 的选取依据。若无法给出依据，改为"每电路取其时序驱动映射可达关键路径延迟的 0.85 倍"这类**相对设定**，使违例落在 15% 量级。此项需重跑。【需外部资源】不重跑的替代：在行 256 增加一段"约束设定说明"，承认这是统一的、与工艺无关的压力设定，并声明**绝对 WNS 不可与工业签核数值比较**，只用于同源相对比较。
  - b20/b21 的 −13 ns 结果在正文（行 331、表 3 行 346）被并入"平均 0.43 ns"，虽然作者做了分层，但仍应显式写一句"该二例的平均改善主要反映其巨大的基线违例，不应作为方法能力的代表"。

**C5｜只报 WNS：无 TNS、无 hold、无 max_tran/max_cap、无功耗、单角（且 setup 用 TT），与"签核"定位不符**

- **位置**：行 400（"功耗、hold、最大电容及转换时间未作为本组验收项"）、行 421（OpenROAD 参数：TT25℃/1.8 V）、行 256、行 162（"每次比较使用同一库、时钟和分析角"）、行 463（结论）。
- **问题**：
  1. **setup 用 TT 角**。数字签核中 setup 必须在 slow corner（SS、低电压、高温）检查，TT 是 nominal。用 TT 报 setup WNS，得到的数值既不保守也不可签核。这与稿件反复出现的"物理后验""签核级提取"（行 435 自谦为非签核）语境冲突。
  2. **G（同族升档）与 B（在接收引脚前插 buffer）恰恰是最容易恶化 max_tran / max_cap 的两类动作**：升档提高输入引脚电容，加重前级驱动负载；插 buffer 在被插引脚前增加一个负载。稿件完全不查这两项，等于**假定被优化的网表在电气规则上仍然合法**——这是预布局阶段唯一能廉价检查的正确性维度，却被整篇跳过。
  3. **无 TNS**。行 162/220 定义了 TNS 且把它作为硬门（$\Delta_{\mathrm{TNS}}\ge 0$），但 4.1–4.3 从不报告 TNS 变化。WNS 改善而 TNS 恶化正是局部升档的典型副作用（把最差路径修好、其余路径变差），既然接受规则里已有这道门，就必须把"被该门拒绝的候选比例"报出来。
  4. **无 hold**。升档与插 buffer 对 hold 的影响方向不确定，任一方向都可能制造新违例。
  5. **无功耗**。0.27%–4.92% 的面积增长全部来自升档，动态功耗与漏电必然上升，稿件却说"不是功耗估计"（行 400）——那就等于说**成本只报了一半**。
  6. **单角单模**，无 OCV/AOCV、无 SI/crosstalk。
- **修改建议**：
  - 行 400 的那句话**不能作为免责**，应升级为独立小节或在 5.1 展开 3–5 句，明确"本文的接受判据不含任何电气规则、功耗与 hold 项，因此被接受的候选在实际实现中可能引入新的 max_cap/max_tran/hold 违例"，并把它列为首要局限。
  - 【不依赖新实验的替代改法，建议采纳】用**已有的初/末网表 + SKY130 Liberty**（无需 STA）计算并报告：(a) 每个被改动网的总引脚电容变化 $\Delta C_{\mathrm{pin}}$ 与相对变化；(b) 基于 Liberty `leakage_power` 与单元实例数的**静态漏电增量估计**。二者都是网表与库的纯后处理，可以给出"负载增量"与"漏电代价"两张小表，直接把"只报面积"补成"面积 + 负载 + 漏电"三元成本。这比补一整套功耗分析便宜得多，且完全回应本审稿点。
  - 报告被 $\Delta_{\mathrm{TNS}}\ge0$ 硬门拒绝的候选数（数据已在台账中），放在 4.1 或补充材料。
  - 【需外部资源】至少在 SS 角复测 8 电路矩阵的终点 WNS。若无法补，则必须在行 256 与 5.1 明确写"TT 仅用于相对比较，本文任何绝对 WNS 数值不代表签核结果"，并删除正文中一切暗示签核的措辞。

**M5｜动作空间的实际内容与术语：B 从未被接受，JOINT 是固定取前两个 G，R/G/B 与经典含义不符**

- **位置**：行 199（动作定义）、表 6（行 409–416，**全部电路缓冲前/后 = 0/0**）、行 327（"没有单独 B"）、行 94/113（摘要列出四类动作）、补充材料行 153（JOINT 构造）。
- **问题**：
  1. **在受控 72 次矩阵中，B 动作一次都没有被接受**（表 6 的"缓冲前/后"8 行全为 0/0），单轮实验也"没有单独 B"（行 327）。因此摘要"枚举…缓冲器插入及联合动作"虽然字面成立（枚举了），但**读者会误以为 buffer insertion 是有效贡献**。实际在核心实验中，动作空间退化为 {同族升档, 同功能换族, 两个升档}。
  2. "JOINT"取"前两个可执行 G 的实例、各选首个 G"（行 199、补充材料行 153）——这是一个**固定的两门升档组合**，不是联合优化。为什么是 2 而不是 3 或按 slack 排序选，文中无依据。而单轮 8 例中 4 例由 JOINT 接受（行 327），说明**主要收益恰恰来自"同时改两个门"**，这进一步削弱了区域/调度机制的解释力。
  3. 术语：
     - **"gate sizing"** 在此只做同族**升档**（G 仅枚举更大驱动尺寸），不含降档；而 sizing 的经典含义含双向调整并用于功耗-时序折中。应写 "discrete up-sizing"。
     - **"equivalent replacement"（R）** 实为"不同单元族但布尔函数与引脚角色相容"的换单元，业界更常称 **cell swapping / technology remapping**；把它译作"逻辑等价替换"容易与 functional ECO 的"逻辑等价变换"混淆。
     - **"buffer insertion"（B）** 只做"在合格接收引脚前插 buf_1 或 buf_2、只重接该引脚"，这是**单级 driver-side buffering**，与经典 buffer insertion（van Ginneken 式树构造）不是同一问题，不宜直呼 buffer insertion。
     - **"ECO"** 的误用见 C1。
- **修改建议**：
  - 摘要与 3.3 节把动作描述改为准确表述："同功能换族（cell swapping）、同族升档（discrete up-sizing）、单级缓冲插入（single-stage driver-side buffering）与两门升档组合"。
  - 在表 6 的表注中**显式写出"受控矩阵中 B 类候选无一次被接受，缓冲单元数前后不变"**，并在 4.1 用一句话说明"动作空间的实测有效部分为 R/G/JOINT"。这是用现有数据就能做的诚实披露。
  - 为 JOINT 的"2 门"给出理由（例如：候选枚举成本随门的组合数指数增长，2 门为首个可行折中），或增加"按 slack 排序选前 k 门"的说明；若无法给理由，明确写"该构造是工程折中，未做最优性论证"。

## 领域贡献定位：相对已有 ECO 工作，这篇稿子到底新增了什么

**真正站得住的三点（建议围绕这三点重写贡献陈述）**

1. **一套可复核的候选记账框架**：把"局部构造检查 / 候选 STA / 最终 SEC"三类成本分开计数，并把缓存命中与前置拒绝排除在新 STA 之外（行 150、214、295）。这在 ECO 文献里经常被糊在一起，本文的口径是可复用的方法学贡献，虽然不大，但真实。
2. **一组自证否定的负结果，且否得很干净**：加权节点割区域在本设定下零增益（W0/U0）、加权与统一容量不可区分（W1≡U1）、结构性重综合的深度下降 76/126 例但 WNS 改善 0/126（行 390）、EMA 反馈无终点收益（行 388）。**"什么样的机制看起来合理但实际不work"**，对领域是有信息量的，尤其"逻辑深度下降不转化为时序改善"这条，值得单独成段强调。
3. **一个可量化的负载敏感性阈值**：同一候选对从 $\ell=10$ 到 $40\,\mu$m 就使 0.15 ns 的理想线网增益归零（表 7）。若能把它从"又一个理想线网不准的例子"重写成"130 nm 下单网约 40 µm 负载即为符号翻转阈值"，这是全篇最像"领域知识"的一句话。

**不构成新增的（必须从标题/摘要/结论中撤下）**

- **"以关键实例/关键路径上的单元为优化对象"**——这是时序驱动优化的定义，不是本文的发现。覆盖区域 $C_c=P\cap C_i$ 就是把 STA 报告实例取交集，其有效性几乎由定义保证；W1 相对 W0 的全部增益（0.161 ns vs 0）本质上就是"从不用时序信息"到"用时序信息"的差别，属一阶效应，不是机制洞察。
- **加权最小割作为候选边界**——图割在时序优化中不是新工具；且本文数据已证其在本题无效（C2）。
- **"预布局时序估计偏乐观"**——已知问题（M2），只能作为定量实例，不能作为发现。
- **"测量成本可以用 STA 次数衡量"**——在 19% 预算利用率、无外部基线的条件下，这个计量尚未被验证为有决策意义的资源（C3）。

**一句话定位（供作者参考改写）**

> 本文不提出一种新的 ECO 修补算法；它提出一个可复核的**候选组织与测量记账框架**，并用 72 次同源受控运行证明：在预布局门级、单库单角、8 个小规模电路的设定下，候选范围的收益几乎全部来自"把 STA 报告实例纳入修改集合"这一阶效应，而加权割代价、区域合并、失效反馈与结构候选均未产生可观测增益；同时给出该增益在 40 µm 级线载下即消失的定量边界。

按这个定位重写，文章的诚实度会成为优点；按现在的"提出 FAECO 方法"定位，上述每条负结果都会反过来成为攻击点。
