## 本轮做了什么

1. **证伪验收仪器（两个根因）**
   - **根因 A（假绿、成组）**：`scratch/accept_falsgreen.py` 的 `w()` 把 WSL 路径原样交给 **Windows venv python**（该解释器是这里唯一有 numpy 的，链也用它）。Windows python 读不了 `/mnt/d/...`，会去找 `D:\mnt\d\...` → **文件不存在** → 工具在"找不到输入"处退出；判定式又只判 `rc != 0` → **"门正确拒绝"、"找不到输入"、"工具崩溃"三者不可区分**。上一轮 A/B/C 三组的"全过"因此不成立。**副作用（物证）**：那轮验收在**工作区外**建出了 `D:\mnt\d\...\scratch\...`（29 目录 / 20 文件），它连自己的产物都没落在工作区。
   - **根因 B（假红）**：`scratch/selfcheck_sync_gate_line_range.py` 是这一批脚本里**唯一**把仓库根写死成 `/mnt/d/...` 的 → 同一台 Windows python 下模块级 `FileNotFoundError` → rc=1、stdout 空 → 验收记成"反向对照失败（-1 failed）"。**工具没跑起来 ≠ 被检对象失败**。
   - **修法**：`w()` 改用 `wslpath -m`（与链同源）；自检脚本根改 `Path(__file__).resolve().parents[1]`；判定式由 `rc != 0` 收紧为「**输入必须真实存在** + **具体期望退出码** + **工具必须出声** + **stderr 不得含 traceback** + **拒绝理由不得是"文件不存在"**」，并把「工具错误」与「语义判决」分开（工具错误重试一次后仍记 FAIL 并标 `TOOL ERROR`）。
   - **真实数字变了**：B 组拒绝的退出码是 **8**（不是上一轮记的 7）——理由经核对为真的覆盖率门（`1393 of the 1393 planned key(s) are MISSING`）。**教训：假绿会污染验收者的预期**，按假数字写下期望码，差点把一次正确的拒绝判成失败。
2. **演练适配闭合**（子任务执行、主线独立复核）：链新增 `--prereg` 通路并把 `--expect-pairs` 一起下传；`post_ext_prereg_check.py` 新增 `--expect-pairs`（**默认 58，默认路径逐项等价**；非 58 必须带 `synthetic_expect_pairs:true` 与文本合成标记）；两个演练的 fixture 自备 `JOB_TABLES.sha256` 与合成预注册，断言收紧为"具体退出码 + 理由"。主线独立复跑：**v1 全绿、v2 全绿**，Windows venv python 下 v2 亦全绿；另做独立对照 **7/7**（默认仍拒绝 6 对读数、显式 6 才放行且带标记、`--expect-pairs 58` 与默认等价）。
