## 0. 一句话结论

意见的**总体方向判断正确**（Failure-Aware 未被独立证明、G 类占主导、物理反馈偏弱），但其**最有价值的一条被误诊**：意见认为"Algorithm 1 不叠加补丁 → 更像找最佳补丁"，事实相反——**主实验实际已是逐轮累积的迭代 ECO，是论文把方法写成了"不叠加"**。这意味着该条不是"要做新机制"，而是"要把已实现的行为写对 + 补 rollback 保护"，成本远低于意见估计。真正需要新做的、价值最高的是 **S（局部重综合）候选**，且其工具链**已经全部存在**（ABC + SKY130 CEC 历史已解决）。

## 2. 可行性评估

评估维度：改动面（哪些文件/流程）、依赖（是否需要新增能力）、成本（人力/算力）、风险。

| 项 | 改动面 | 依赖 | 成本 | 风险 |
|---|---|---|---|---|
| **A. 论文口径修正**（Algorithm 1 叠加描述、§4.2 策略分布） | 仅 tex | 无 | 小时级 | 低（纯事实对齐） |
| **B. Mixed+固定权重消融** | 仅实验配置：`enable_feedback=False` + 全候选空间（R/G/B/JOINT） | `refinement_loop.py:81` 已有开关 | 重跑 27 电路 × 1 配置；按主实验 3363 次 STA ≈ 2.4 h 墙钟（2 路并行）→ **1 天内** | 低 |
| **C. 失败率驱动权重**（ρ、η 归一化更新） | `refinement.py` 单函数 + 新增 2 个参数 | 无 | 改 1 天 + 重跑验证 | 中：需防"改动主机制导致既有结论变化"，须保留固定权重版作对照 |

## 4. 与意见的差异（需向评审反馈的判断）

1. **第④条被误诊**：不是"FAECO 缺少真正的迭代 ECO"，而是"FAECO 已经是迭代 ECO，但论文写成了单候选选择"。修正方向是**写对**而非**新做**，成本从"★★★★☆ 重构算法"降为"论文改写 + rollback 加固"。
2. **第③条的"B/R 覆盖低"不成立**：B 覆盖 14/19 电路，参与度仅次于 G。准确的批评应是"**收益幅度**由 G 主导"（G 单次平均改善更大），而非"覆盖低"。
3. **第⑦条部分不成立**：`accept` 谓词已含 TNS 分支（`tns_aware`），只是主实验未启用。建议改为"**在主实验中启用并报告 tns_aware 的结果**"，而不是"新增 TNS"。
4. **第⑧条被高估为"新增指标"**：`logic_level_*` 字段已在 schema 中（sprint1 有坑位），属"补采集"而非"新建能力"。
5. **第⑤条的硬前置被忽略**：电气量当前覆盖率 0，前置之前必须先补采集，否则是把未标定的量塞进主代价（与论文现有 limitation 叠加成新风险）。
6. **第⑦/⑨条与 SEC 位置的冲突未被识别**：词典序把 SEC 放首位在工程上不可行（SEC 是网表级、单次 17 s 量级且需完整网表），须改为"候选级 CEC + 网表级 SEC"两层。
