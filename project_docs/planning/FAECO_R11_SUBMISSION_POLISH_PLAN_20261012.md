## 2. 阶段 1：贡献定位重写（定稿草稿）

### 2.1 病根

现行 §1.3 三条贡献的**标题**是「多特征候选构造与排序 / 候选失效分类与搜索控制 / 迭代 ECO 与分层验证流程」，全部以**技术构件**命名；审稿人第一眼会读成「加权割 + gate sizing + buffer + 失效分类 = 已有组件拼装」。用户方案指出：应把**主贡献名词**从"新算法"改为"候选探索与验证框架"。

### 2.2 草稿 A：§1.3 增加一句定位导语（放在「本文的主要贡献如下：」之后）

```latex
本文的贡献不在于提出新的割算法或新的物理优化算子，而在于把预布局门级时序 ECO 中的
候选空间管理、验证代价控制与失效诊断整合为一个可在公开工具链上复现的探索框架。
```

### 2.3 草稿 B：三条贡献改写（替换 L139–143 的 `enumerate` 内容）

```latex
  \item \textbf{预布局门级 ECO 的候选探索框架}：面向综合后、布局前的已映射网表，提出统一管理
候选空间与验证代价的探索框架——在违例扇入锥内以多特征加权割与关键路径覆盖割生成
R/G/B/JOINT 候选，并按割代价、关键路径覆盖及策略优先级排序。式~\eqref{eq:cost} 中的特征
（边界、候选规模、验证代价、扇出、逻辑深度）用于形成\emph{候选排序偏置}，权重在全部实验中
取固定值，以检验框架在统一配置下的稳定性而非权重的最优性。在固定权重、20 轮迭代实验中，
混合候选策略的平均 WNS 改善为 1.07\,ns，高于纯 G 策略的 0.16\,ns。
  \item \textbf{类型化失效刻画与搜索参数控制}：将候选失效划分为功能与结构、边界、尺寸、
时序收益、验证超时与物理复测六类（F1--F6），用于\emph{搜索诊断与候选控制}——为下一轮候选
构造提供输入，而非独立的收敛增益来源；固定权重与 EMA 自适应反馈的对照实验显示两者在
8 个 ISCAS89 电路上的终点逐位相同，据此本文不将自适应反馈列为独立贡献。
  \item \textbf{迭代提交与分层验证流程}：构建按轮提交的门级 ECO 流程与统一数据流……
（后半段沿用原文，不加改动）
```

**改动要点**：① 标题名词从「多特征候选构造与排序」→「**候选探索框架**」；② 动词从「提出融合…的加权割」→「以…生成候选」（**去掉"提出"对割算法的冠名**）；③ 显式写入"排序偏置 + 固定权重非最优"；④ 贡献 2 标题从「失效分类与搜索控制」→「**失效刻画**与搜索参数控制」（`attribution`→`characterization`，与阶段 4 一致）。

## 4. 阶段 4：英文标题 5 候选 + 排序

### 4.1 现行

`FAECO: Structured Candidate Search and Failure Attribution for Pre-Placement Gate-Level Timing ECO`

### 4.2 ★ 先提一个风险（会影响排序）

用户方案想把 `Failure Attribution`（略强）降级。但需要注意一个**方向性矛盾**：

> §4.4 第二组实验的结论是 **EMA 失效反馈相较固定权重"未取得额外收益"**（`.tex` L488），且贡献 2 已把 F1–F6 定位为"搜索诊断，而非独立增益来源"。因此**把 `Failure-Aware` 放进标题**（用户方案 1）等于把"失效感知"当作卖点，反而**主动邀请审稿人问"那你的失效感知为什么不涨点？"** —— 与正文的降级口径自相矛盾。

⇒ 排序应以**`Candidate Exploration` 为头名词**为第一优先，`Failure Characterization` 作次要限定；`Failure-Aware` 排后。

### 4.3 候选与排序（推荐序）

| 排名 | 标题 | 头名词 | 优劣 |
|---|---|---|---|
| **1** | `FAECO: Candidate Exploration and Failure Characterization for Pre-Placement Gate-Level Timing ECO` | Candidate Exploration | **最平衡**：头名词=探索（正对阶段 1 定位）；`Characterization` 弱于 `Attribution`；长度适中；与中文题「结构化候选搜索与失效归因」仍可对上（归因→刻画） |
| **2** | `FAECO: Structured Candidate Exploration for Pre-Placement Gate-Level Timing ECO` | Candidate Exploration | 最干净、最短；但**完全丢掉失效线**，F1–F6（占 §3.3 + 表 4/表 9）在标题里无位置，略有"标题小于内容" |
| 3 | `FAECO: Structured Candidate Exploration and Failure Characterization for Pre-Placement Gate-Level Timing ECO` | Candidate Exploration | 用户方案 2，最准确；**但过长**（126 字符），Elsevier 排版易折两行 |
| 4 | `FAECO: Failure-Aware Candidate Exploration for Pre-Placement Gate-Level Timing ECO` | Candidate Exploration | 用户方案 1；FAECO 恰好可读作 **F**ailure-**A**ware **ECO**；**但踩 §4.2 风险** |
| 5 | `FAECO: Verification-Aware Candidate Exploration for Pre-Placement Gate-Level Timing ECO` | Candidate Exploration | 独辟蹊径：把卖点放在**验证代价控制**（用户方案阶段 1 的三大要点之一，且 v8 新增 runtime 表正好支撑）；缺点是与"失效"线脱节 |

### 4.4 建议

**取 #1**。它同时满足用户三条约束（保留 FAECO / 不夸大 failure / 突出 candidate exploration + pre-placement gate-level timing ECO）。若求最短则 #2，但需接受"标题不含失效"。
**注意**：中文题建议同步微调（如「…候选探索与失效刻画」），否则中英标题口径分裂。

## 7. 阶段 3：cost 消融（OI-026）—— ★ 关键取证 + 可行设计

### 7.1 ★ 取证结论：用户设想的 arms **在当前 runner 上不可实现**

用户方案要求消融式(2)的五个特征（boundary / size / verification / fanout / depth）。取证结果：

1. **§4.4 表 6、表 8 出自族 C，其运行器是 `code/scripts/run_hybrid_repair.py`**（旁证：产物目录含 `cand_hybrid/`、`hybrid_result.json`、`mapped_hybrid.v`、`round_current.v`，均为此脚本唯一写出路径；族 C 定义见 `PAPER_EVIDENCE_MANIFEST.md`：运行器 = `run_hybrid_repair.py`，不使用 `refine_weights`/`enable_feedback`）。
2. **该运行器的排序层完全不读取 `cost(v)`**：它从 OpenSTA 直接解析关键实例，逐实例枚举 R/G/B 候选，排序仅由 `--strategy-priorities`（策略优先级表）+ `exploration_order()`（把 G/R 提升到 B 之前）+ 可选 `--random-order` 决定。其 `parse_args()` 的 **全部参数中没有任何 λ**。
   ⇒ **"Base / +boundary / +size / +verification / Full" 在族 C 上没有可切换的量**，该实验**无法**在表 6 的 runner 上运行。
3. `cost(v)`（式 2）实际实现在 `code/src/rseco/cut.py` 的节点代价函数（L182–212）：
   - λ_b → `boundary_penalty`（L182/199）、λ_s → `size_penalty`（L183/201）、λ_c → `critical_coverage_reward`（L184/208）、λ_v → `verification_cost_penalty`（L185/202）、λ_f → `equivalence_stability_reward`（L186/200）。
   - 权重对象来自 `code/src/rseco/real_wns.py` 的 `init_weights`，**只有 3 个键**：`boundary_penalty` / `size_penalty` / `critical_coverage_reward`（= λ_b/λ_s/λ_c）；**λ_v 与 λ_f 无初始参数**，靠 `getattr(..., 1.0)` 兜底。
   - CLI 侧 `run_outerloop_real_wns.py` 已有 `--init-boundary-penalty` / `--init-size-penalty` / `--init-critical-coverage-reward`（L190–194），**无 verification / stability**。
4. 而使用 `cost(v)` 的这条路径（族 D，`run_outerloop_real_wns.py`）**复现不出表 6**（已证：s27 首次改善 **1 vs 30**、random 均值 ΔWNS **0.40 vs 0.265**、fixed **0.285 vs 1.07**）。

**⇒ 两条硬结论**：
- (a) 消融**必须**换到使用 `cost(v)` 的运行器，且**必然属于新族（记 C′）**；
- (b) 其结果**不得**并入表 6 / 表 8，**必须**新表 + 表注声明"与表 6/8 不同族，不可跨表比较"。
- （这正是 r10 的教训 ③ 的重演：*"某族有该字段" ≠ "该族能支撑该表"*。）

### 7.2 可行设计（族 C′）

- **运行器**：`code/scripts/run_outerloop_real_wns.py`（唯一真正消费 `cost(v)` 的公开运行器）。
- **与族 D 同源配置**，保证臂间可比：`--max-iterations 20 --sta-budget 500 --no-feedback --strategies R,G,B`、`--period 0.5`、8 个 ISCAS89、`--iscas89-dir` 默认。
- **臂定义（增量式，只改 λ，其余一切不变）**：

  | 臂 | λ_b | λ_s | λ_v | λ_f | λ_c |
  |---|---|---|---|---|---|
  | Base（无特征排序） | 0 | 0 | 0 | 0 | 0 |
  | +边界 | 1 | 0 | 0 | 0 | 0 |
  | +尺寸 | 1 | 1 | 0 | 0 | 0 |
  | +验证 | 1 | 1 | 1 | 0 | 0 |
  | +扇出 | 1 | 1 | 1 | 1 | 0 |

  （理由：与用户方案的 5 行增量表一致，但补齐 λ_f 一行，使"五项齐备"可验证。）
