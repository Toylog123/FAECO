## 3. Stage 2B：原生 `recover_power` 保护后端对照

240 s 单次路由上限的第一遍，SKY130HD AES 120 项与 riscv32i 24 项两臂各达到路由上限。用修正后名称规范化与冻结源 master 复查原件，ASAP7 UART 两臂各 16/16 项确实无法绑定，提议 SHA-256 269d62f05c711c9177d5ad07ebca53b0d33668f110c5ba2ed9cc397dcd24d44c。ASAP7 AES 两臂各缺 142/174 项，余 32 项源 master 全匹配，提议 SHA-256 b584b04793a5b36b151e741228433cfb0f5cc3214c657d01c56d5acdf18a51ae。两设计现有原生完整提议未进入同后端物理比较。SKY130HD 600 s 重试为两设计的原生标准档与允许 Setup 违规档。首次真实诊断在 120 项已绑定、清除 241 条直连走线后，窗口 Tcl 使用逻辑规范名查询包围盒失败，预检返回 1。该次主动中断，保留诊断日志与独立尝试目录。[故障与归因](../../OPEN_ISSUES.md#oi-1082026-11-26open原生整批动作的实例身份与保护后端可评估性)

## 4. Stage 3–5 待实跑结果
