# 第 34 轮 —— 候选在理想线网上"从未被测量"：理想档保持为空，并让缺口可见

## 本轮发现了什么

候选级物理标签族在从 ledger 到训练表的链路上**丢候选**。根因既不是键匹配，也不是门效应：
ECO 循环**根本没有在理想线网上评估过**一部分候选，而数据集构建器只从一个
"只有被评估过的 trial 才有的字段"里取理想档读数。

* 构建器只从 `trial['acceptance_evidence']['setup_wns']` 取候选的理想档 WNS，
  只从 `trial['acceptance_evidence']['metric_references']['setup_wns']` 取迭代基线。
* **从未产生接受决策**的 trial **不带** `acceptance_evidence`，于是两个读数都空，
  候选的理想档标签被**静默留空**。
* 三点曲线随后把"理想档为空"的候选全部 `continue` 掉 —— 这同时扔掉了该候选
  **真实的**布局后/布线后测量：被丢掉的候选根本进不了训练表。

## "显然的修法"为什么是错的（以及它被回滚了）

显然的修法是回退到 ledger 的 `trial['wns']`。这个回退在**同时带有两个字段**的 trial 上
与主字段**完全相等**（ITC-99 3734/3734、ISCAS89
332/332，0 处不符），看上去很安全。

它不安全，因为**需要回退**的那批 trial 两个字段**都没有**，而对它们来说 `trial['wns']`
不是测量值：

* 在 310/310 个受影响的 ITC-99 trial 上，它**恰好等于**
  迭代基线的 WNS（ISCAS89 是 25/25）；
* 它**没有** `sta_provenance`（0/310 有），
  而被测量的 trial 是 3734/3734 全有；
* 它没有 `slack_status`、也没有 `min_slack`；
* 它们的失败事件是 **STA 之前**的硬门（F1 等价性失败、F2 边界非法）；
* 按候选哈希匹配"本轮被接受候选"的只有 0 个。

用这个占位符去填理想档，等于断言"该候选在理想线网上恰好中性" —— 而 ledger 从未做过
这个测量。第一版补丁正是这么做的，并被"它移动了决策级参照读数"这一事实抓住
（b01/2 的 `gain_impl` 0.01 -> -0.01、`impl_key` t022 -> t021：被伪造的标签让一个
**不同的**候选看起来像是循环自己的选择）。该补丁已回滚。

## 实际落地的修复

1. 构建器把理想档标签**保持为空**，并记录真正已知的东西：`ideal_label_status`
   （`measured` / `not_measured_pre_sta`）与 `ideal_wns_placeholder`
   （ledger 的原值，标明它是基线的）；
2. 三点曲线**保留**这些候选 —— 它们的布局后/布线后档是真实测量 —— 并且每个 stage
   统计都按"带有该档测量的子集"计算（它本来就是这样算的）；
3. 曲线旁新增 **drop 普查**产物，逐类计数每个候选被丢弃的原因，让静默丢弃不可能再隐身。

## 决策级读数没有动，而且这是正确的

第 33 轮的决策级分析要求候选**三档齐全**才能进入决策池，因为一次决策比较的是
**理想判据**与**布局后判据**。新补上的这 76 个候选**没有理想档测量**，因此留在池外，
读数不变：ITC-99 27 个可评估决策（8 胜 / 5 负 /
14 平，p = 0.5810546875、挽回 0.073171、H1 触发：
False）；ISCAS89 14 个决策（1/2/11，
p = 1.0、挽回 0.055556、H1 触发：
False）。

## 下游级联

两族各自的分析链**原样重跑**。ISCAS89：**0/23** 个产物变动。ITC-99：**8**
个产物变动，形态一律是"样本 +76、比值微移"：`acceptance_selectivity.json`, `band_scope.json`, `kind_g_vs_r_probe.json`, `stage_kind_effect.json`, `stage_quant_floor.json`, `stage_verdict_transfer.json`, `structural_features_summary.json`, `surrogate_cross_stage.json`。

`band_scope.json` 里另有一个数字也移动了，而它**与本补丁无关**：
`stored_ratio_in_three_point_curve` 2.933548 -> 1.668075。
曲线自身的两个带在补丁前后**逐位相同**，而 `band_scope_itc99.py` 自测的
`ratio_routed_over_placed` 两侧都是 1.668108 —— 两个字段是同样两个带
的比值，不可能合法地不同，其中一个是陈旧值。陈旧值可被精确复现为
0.087496 / 0.029826 = 2.933548，
即**pilot 口径**布线后带除以**全样本**布局后带：这是第 22 轮换带后遗留的**跨口径**比值。

## 本轮**不主张**什么

* **不主张**这 76 个候选的理想档是零：它是**未测量**，而现在数据集明确写成未测量；
* **不主张**决策级的画面变了：它没有变，理由见上；
* 探针测的是每电路一次基准跑，因此它只给扩面**定价**，
  **不能证明**可达电路的每个候选都能成功布线；
* 这里每个数字都是**探针级、非论文证据**：寄生来自 `estimate_parasitics` 而非签核 RCX，
  且布局后档与布线后档用的是**不同的寄生估计模型**，所以"布线后 - 布局后"里
  混着档位变化与模型变化。
