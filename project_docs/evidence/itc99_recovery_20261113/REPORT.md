# ITC-99 跨设计选择性恢复验证报告

> **目标**: 验证选择性恢复（`code/scripts/recover_area.py`）在 ISCAS89 族之外的设计族上是否具有一致的面积回收能力  
> **日期**: 2026-11-13（初版 9 电路），2026-11-14 ~ 2026-11-16（扩展至 16 电路 + 基线 WNS 补测）  
> **状态**: 16 电路完成评估（14 电路完成有修改恢复，b14 Resizer 0 修改，b22 359 修改逐一弹出回退验证 600s 超时未闭合；b17–b21 合成完成但 Resizer 详细布线超时不可行）  
> **入口**: `experiments/20261113_itc99_recovery/`

## 1. 实验流程与口径边界

每个电路经过三个步骤：
1. **Yosys 综合**（RTL → `mapped.v`，使用 `sky130_fd_sc_hd` 库）。
2. **OpenROAD Resizer 时序修复**（`period=0.5 ns, util=0.35, density=0.55`）。
3. **选择性恢复**（`recover_area.py`，`max_degradation=0.015 ns, safety_factor=1.5`）。

> **重要口径边界（对照 OI-082 / OI-085）**：
> - 本批实验复用 Resizer 产出的固定 `routed.spef` 与理想时钟（`sta_routed`），**未对回退后的网表重新执行合法化、详细布线、新 RC 提取及传播时钟 STA**，也未执行全网表 SEC。它属于固定寄生诊断/选择性恢复口径，不等同于 `s382` `RESTORE074` 的重布线物理签核验收。
> - 表中 `base_area / resizer_area / recovered_area` 来自 `recover_area.py` 的 `\w+` 正则解析器（跳过转义名触发器实例，见 OI-085）；绝对节省面积 `area_saved` 与全解析一致，而新增面积回收率分母为 `resizer_area - base_area`（同名导出单元净增面积）。
> - 基线 WNS（`baseline_wns.json`）由 OpenROAD 26Q3 零线延迟理想 STA（含 LEF）测得。

## 3. 关键发现与机制启示

1. **14 个完成恢复电路的一致性**: 在完成恢复闭合的 14 个电路（`b01–b13, b15`）上，共回退 `501 / 612`（`81.9%`）个 Resizer 同名门尺寸修改，回收面积 `3026.66 / 12635.87 µm²`（加权回收率 `23.95%`，算术平均 `18.95%`），所有电路时序退化均受控在 `max_degradation = 0.015 ns` 门限内（最差为 `b11` 的 `−0.0115 ns`，最优为 `b15` 的 `+0.0162 ns` 与 `b09` 的 `+0.0153 ns`）。
2. **`b22` 暴露线性回滚与单门独立假设的瓶颈**: `b22` 的 359 个修改在单门回退测试中全部测得 $\delta\text{WNS}=0.0000\text{ ns}$，但同时回退时因多门负载/串扰累积耦合产生超限退化；而现有 `recover_area.py` 第 375 行每次只 `pop()` 1 个门并重跑整网表 STA，导致需要数百次 STA 验证而超时。**这是下一步算法改进（用二分分块回滚或有界组合搜索替代单步线性回退）的直接工程切入点。**
3. **大规模电路（`b17–b21`）流程边界**: `b17–b21` 已完成 Yosys 综合（`experiments/20261113_itc99_recovery/inputs/`），但 OpenROAD Resizer + 详细布线流程在单电路 30–56 分钟内未能收敛完成，记录为流程超时未评估。
