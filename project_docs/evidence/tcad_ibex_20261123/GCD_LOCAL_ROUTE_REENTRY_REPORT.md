# GCD 从限域详细布线状态续跑

2026-11-25。旧预筛在两轮详细布线后仍无法正确区分两个等面积候选，对 `_093_` 的有利时钟改线在之后出现。这一轮给续跑最有利的条件，保留中间布线和已做的 pin access，跳过中间寄生和 STA，只在最终布线后从原 SDC 和寄生重新验收。 [前一轮预筛证据](GCD_LOCAL_HOLD_PREVIEW_REPORT.md)

## 运行前规约

冻结两个累积候选 `_089_/_090_/_091_` 和 `_089_/_090_/_093_`，使用历史 GCD 冻结 ODB、嵌入导引、原 1100 ps 时钟和 I/O、原 SS／TT／FF Liberty 与同一 OpenROAD。CPU 6–11、布线 4 线程。从头法沿用原未锁网详细布线（64 轮上限）。续跑法沿用上轮 452 条网固定的两轮限域布线，保存中间 ODB 和 DEF。同进程内将固定线的编码改为 ROUTED 并读回，核对所有网的几何、连接、布图和导引，再向同一个 block 发起第二次详细布线，显式 `-no_pin_access` 复用已有 AP，保留中间线段，无换门和清线。第二次调用仍会重新初始化 DRT 搜索。

第一组按从头 `_091_`、续跑 `_091_`、从头 `_093_`、续跑 `_093_`。第二组按续跑 `_093_`、从头 `_093_`、续跑 `_091_`、从头 `_091_` 执行。每个候选重新评估。完整用时包含生成限域网范围、工具启动、中间保存与解锁、布线、最终耦合 RCX、逐角 STA、独立全块 DRC 和天线检查。对完成物理产物且网表身份无误的端点做 SEC，即使原门拒收也独立记录证明账。另报按原接受时才运行 SEC 的口径。

维持原 setup 预算和各角 hold 门，TT/SS WNS 原下限分别为 430.725704 ps 与 342.904315 ps。各候选在两种方法下要获得相同的原门验收判定，最后全块 DRC、天线和 SEC 均通过，且两个运行顺序的总墙钟都下降，才支持该续跑配方。若最终几何或 SPEF 有差异，按不同物理端点重新解释，不把更快的另一端点视为重现了原布线。

## 新进程重入消融的预登记

同进程首个 `_091_` 的第二次布线报告 0 个违规后连通检查失败。另做新进程重入，以区分保存的物理几何问题和进程内的路由状态。第一进程照样完成限域两轮并保存锁定 ODB。第二进程读该 ODB，在执行 DRT 前才解锁、核对导引和几何，然后跳过 PA，继续原配方至最终验收。两次工具启动、保存、读入与解锁全部计入同一候选的 RAW 总墙钟，双序和原门照旧。

## 同进程续跑

同进程四次续跑均没有产生可做最终验收的端点。`_091_` 两序在 9.383／10.485 RAW s 结束，第二次 DRT 报 0 个违规，但 `design_is_routed` 返回假。`_093_` 两序进入后续修复迭代，至 100.212／100.281 RAW s 超时，最后可见 2 个未解决违规。两个候选均无续跑终帧 RCX、STA 或 SEC。同期从头从冻起点布线的四次均走完全链并复现旧判定。

两种进程方式的全部 8 份检查点在解锁前后，486 条 DEF 网的规范化几何和连接、组件、特殊网与导引逐项一致，452 条 FIXED 全部释放。第一段实际执行 1 次 PA，恢复段 0 次。布线器实际读取了检查点的 7／17 个违规标记，并从第 3 轮开始恢复。该构建会新建详细布线搜索对象，进程内读取可能复用既有路由数据。同进程的失败终态未写出，无法确认具体缺线网或把不布通归结到单个内部标记。 [同进程结果](GCD_LOCAL_ROUTE_REENTRY_RESULTS.json) · [检查点独验](GCD_ROUTE_CHECKPOINT_AUDIT.json)

## 判断与后续

续跑作为加速方案未达到预期。新进程恢复的价值在于为 `_091_` 提供一个通过原门的备用物理端点。下一步优先测完整布线因相对 hold 拒收、且池中缺少等面积合格端点时，检查点重入是否值得作为补救。仍用原门验收，并记录从拒收到达标的额外耗时、回收面积和触发次数。若继续探索加速，应先在更短的检查点上测第一段开销和可恢复性，保留全链的同机对照。
