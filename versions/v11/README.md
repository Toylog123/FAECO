## 教训
1. **★ 写 `.tex` 前必须先归一化行尾再落盘（本轮自造事故）**：`apply_r13_abstract.py` 用 `raw.decode()` 直接得到含 `\r\n` 的文本，末尾又做 `t.replace('\n','\r\n')`，把每行变成 **`\r\r\n`**（668 处）。LuaLaTeX 把多出的裸 `\r` 当作额外换行 ⇒ 插入大量 `\par` ⇒ **83 Errors / 2 Overfull / 11 页**。`b.count('\r\n')` 与 `b.count('\n')-b.count('\r\n')` **无法**发现该错误（两者在 `\r\r\n` 下仍分别等于 668 与 0）。**正确写法**：先 `t = raw.decode('utf-8').replace('\r\n','\n')`，处理后再 `t.replace('\n','\r\n')` 落盘；**判据**：额外检查 `b.count(b'\r') == b.count(b'\n')`，或直接断言 `b.count(b'\r\r\n') == 0`。
2. **"用户给的文案"与"论文既有口径"冲突时，以取证为准并显式列出偏离**：本轮草案含 1 处术语错误（工程变更**优化**）与 2 处**回退已落地审稿修复**的风险（删 M2 分母解释、删"其余无退化"）。落地前必须逐句回正文/审稿轮核对，**偏离要明写，不能静默采纳**。
3. **加"大背景"句会放大边界声明的必要性**：背景句抬高问题层级（"时序收敛是芯片设计的关键挑战"），若同时删掉"其余无退化"这一限定，等于把"大问题"与"有限改善"之间的落差敞开给审稿人。**背景越宏大，边界声明越不可删**。
4. **字数规则随投稿目标失效，须复核而非沿用**：摘要「≤300 汉字 / ≤150 词」是 JCAD 征稿简则的规则；改投 Integration 后该约束失效，但**新约束（Elsevier 常见 ≤250 词）须在 OI-028 轮按作者指南正式复核**。沿用失效规则会误判合规性。
