## 本轮教训（写入 `MEMORY.md`）

1. **★ `pdftotext` 默认模式在本文档上会把双栏「逐行交错」输出**（左栏第 i 行、右栏第 i 行、左栏第 i+1 行…），并非"先读完一栏再读下一栏"。因此**跨行片段**（如「影响单次改动的区域范围」被 618 行断在「区域」后、下一同栏行在 622 行）**无法用相邻两行拼接命中**。可行的回读方案 = **四个重建流并联**（全文拼接 / 去空行拼接 / 去空行偶序号流 / 奇序号流）+ **容隙流**（某行与其后 ≤8 个非空行拼接）+ **浮动体打断兜底**（head 为某行后缀、tail 为更后某行前缀）。
2. **浮动体会把段落切成两半**：本文 §3.2 的 `搜索诊断与分析机制` 被算法浮动体的 3 行插在「…定位为搜」与「索诊断与分析机制…」之间，任何连续拼接都无法命中；须用**前后缀分离匹配**兜底。
3. **"全篇拼接"里若保留了换行符仍会漏匹配**：`"\n".join(lines)` 与 `"".join(lines)` 结果不同——去空白后必须**无分隔符拼接**才能跨行命中。
