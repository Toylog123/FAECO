# versions — 冻结版本集合

> 存放冻结版本的**完整开发快照**。每个版本目录是完整体：含该版本的 `code/`（源码+脚本+测试）、`project/`（构建工程）、`experiments/`（实验）与 `docs/`（该版本开发时的相关文档），**零交叉引用**——不引用其他版本或项目级目录的任何文件。

## 主目录 = 最新最好的版本

- 项目根的 `code/`、`docs/` 等始终是**当前最新最好的版本**（活动工作区）。
- 阶段完成 → 打基线 + git tag → 将当前 `code/`、`project/`、`experiments/`、`docs/` **完整复制**为 `versions/<基线ID>/` 冻结快照。
- 复制后该版本自成一体；后续开发在根 `code/` 继续，历史版本不受影响。

## 版本目录结构

```text
versions/
|- v1/
|  |- README.md         # 版本说明（基线、日期、变更摘要）
|  |- code/             # 该版本代码完整副本（源码+脚本+测试）
|  |- project/          # 该版本构建工程 / 配置
|  |- experiments/      # 该版本实验
|  `- docs/             # 该版本开发时的相关文档
`- v2/ ...
```

## 共享与隔离

- 论文（`paper/`）、数据（`data/`）、过程文档（`project_docs/`）为**项目级共享**，由基线与证据交叉表绑定版本，不随版本复制。
- 版本内的 `code/`、`docs/` 等是该版本开发时的完整内容，复制后与主目录解耦。

## 规则

- 版本目录一旦冻结**不可修改**；如需更新，复制出新版本目录。
- 禁止跨版本引用文件（含脚本）；需要即复制进本版本目录。
- 当前在根 `code/` 推进的版本 = `BASELINE_INDEX.csv` 中 `status=active` 的基线。
